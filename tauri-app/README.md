# tauri-app

Native shell for pAInapple Code, targeting **iOS, iPadOS, and macOS** via [Tauri v2](https://v2.tauri.app/).

Two modes:

- **Remote (all platforms):** loads a remote pAInapple Code server URL into a
  native WKWebView. The user enters the server URL once on first launch
  (`src/index.html` is the launcher); after that the WebView navigates to the
  user's server and behaves like any browser tab pointed at pAInapple.
- **Local (desktop only):** the "This Mac" card on the launcher provisions a
  local bridge with the bundled [`uv`](https://github.com/astral-sh/uv)
  sidecar — managed CPython + `uv tool install painapple-code` from PyPI,
  fully isolated under the app data dir — then starts/stops/supervises it
  (`src-tauri/src/local.rs`). No system Python, Node, or Homebrew required;
  the Claude Code CLI gets a one-click official-installer button. Design doc:
  `docs-ai/plans/2026-07-10-desktop-app-macos-local-mode.md`.

See [APP.md](APP.md) for branch goals and open questions, and [CAPACITOR-VS-TAURI.md](CAPACITOR-VS-TAURI.md) for the framework choice rationale.

## Layout

```
tauri-app/
├── package.json              npm scripts + Tauri CLI dev dep
├── src/                      web frontend (the launcher)
│   ├── index.html            URL + token input
│   ├── launcher.js           normalize URL, persist, redirect to remote server
│   └── icon.png              favicon
└── src-tauri/                Rust native shell
    ├── Cargo.toml
    ├── build.rs
    ├── src/
    │   ├── main.rs           desktop entrypoint
    │   └── lib.rs            shared run() — used by desktop + mobile
    ├── tauri.conf.json       window, bundle identifier, frontend path
    ├── capabilities/
    │   └── default.json      permissions (currently: core only)
    └── icons/                generated by `tauri icon` from src/painapple_code/static/icons/icon-512.png
```

## Prerequisites

| | Required for | Install |
|---|---|---|
| Node 20+ | Tauri CLI | nodejs.org |
| Rust (stable) | Native compilation | rustup.rs |
| Xcode 15+ | macOS / iOS builds | App Store (macOS only) |
| Cocoapods | iOS builds | `brew install cocoapods` |
| Rust iOS targets | iOS builds | `rustup target add aarch64-apple-ios aarch64-apple-ios-sim x86_64-apple-ios` |
| Apple Developer account | Device install + distribution | $99/yr — only needed when shipping |

Linux builds additionally need `webkit2gtk-4.1`, `librsvg2-dev`, `build-essential` — not relevant for the Apple-only goal.

## Workflow

From this directory:

```bash
npm install               # one-time; pulls @tauri-apps/cli and @tauri-apps/api

# macOS desktop dev
npm run dev               # launches a window using src/index.html

# macOS desktop release
npm run build             # produces .app + .dmg in src-tauri/target/release/bundle/

# iOS — first time only
npm run ios:init          # creates src-tauri/gen/apple/ (Xcode project)

# iOS dev (simulator or device with TAURI_DEV_HOST set)
npm run ios:dev

# iOS release
npm run ios:build         # produces .ipa
```

## Configuration

- **Bundle identifier**: `com.boothw.painapple` in `src-tauri/tauri.conf.json`. Change before publishing under a different account.
- **Window size / chrome**: same file, under `app.windows[]`.
- **CSP**: currently `null` (unset) — needed because the launcher navigates to arbitrary user-provided origins. Tightening this would require a more elaborate native bridge to handle navigation.
- **Icons**: regenerate with `npm run icon` if `../src/painapple_code/static/icons/icon-512.png` changes.

## Generated files (gitignored)

- `node_modules/`
- `src-tauri/target/` (Cargo build output)
- `src-tauri/gen/` (Tauri-generated Xcode + Android projects — regenerated by `tauri ios init` / `tauri android init`)

## Known limitations (v0)

- **No way to change server URL after connect** except by relaunching the app. The launcher shows on every launch; click "forget" to clear the saved URL.
- **No deep-link handling** for the server's bootstrap `?tkn=…` URL yet. Planned: add `tauri-plugin-deep-link` so tapping a bootstrap URL on iOS opens the app pre-filled.
- **HTTP / WS to localhost** will need `NSAppTransportSecurity` exceptions in `Info.plist`. Not configured yet — current assumption is users will run pAInapple behind TLS.
- **PTY keyboard on iOS** — xterm.js inside WKWebView doesn't get Ctrl/Esc/Tab from the standard iOS keyboard. A custom on-screen modifier toolbar will be needed.

None of these block the initial scaffold — they're tracked here for when we actually start running it on devices.
